# TCP vs UDP

TCP와 UDP는 둘 다 **전송 계층(L4) 프로토콜**이다.
둘의 공통 역할은 **IP 주소로 도착한 데이터를 어떤 프로그램으로 전달할지 구분하는 것**이다.

이때 사용하는 것이 **포트 번호**다.

```text
IP 주소: 어느 컴퓨터로 보낼까?
포트 번호: 그 컴퓨터 안의 어떤 프로그램으로 보낼까?
```

예를 들어 내 컴퓨터에서 크롬, 카카오톡, 게임이 동시에 인터넷을 써도 구분되는 이유가 포트 번호 덕분이다.

## TCP란?

TCP는 **연결형 프로토콜**이다.

데이터를 보내기 전에 먼저 상대방과 연결을 맺는다.

```text
클라이언트: "연결하자. 내 시작 번호는 x야."
서버: "좋아. x 확인했어. 내 시작 번호는 y야."
클라이언트: "y 확인했어. 이제 연결 완료."

"시작 번호"는 TCP가 데이터 순서를 관리하기 위해 사용하는 Sequence Number이다.
```

이 연결 설정 과정이 [tcp 3 way handshake](../tcp%203%20way%20handshake%20%26%204%20way%20handshake/tcp%203%20way%20handshake%20%26%204%20way%20handshake.md)다. 

TCP의 특징은 다음과 같다.

```text
연결형
신뢰성 보장
순서 보장
재전송 가능
흐름 제어 가능
혼잡 제어 가능
상대적으로 느림
```

예를 들어 파일 다운로드 중간에 일부 데이터가 빠지면 안 된다.
로그인 요청, 결제 요청, 게시글 작성 요청도 데이터가 정확히 전달되어야 한다.

**그래서 TCP는 정확성이 중요한 통신에 사용한다.**
- 예) 웹 HTTP/HTTPS , 파일 전송 , 이메일 , DB 연결 , SSH

## UDP란?

UDP는 **비연결형 프로토콜**이다.

데이터를 보내기 전에 연결을 맺지 않는다.
그냥 바로 보낸다.

```text
클라이언트 : 연결 확인은 생략하고, 데이터를 바로 보낼게.
```

UDP의 특징은 다음과 같다.

```text
비연결형
신뢰성 보장 안 함
순서 보장 안 함
재전송 안 함
흐름 제어 없음
혼잡 제어 없음
상대적으로 빠름
```

대신 구조가 단순하고 오버헤드가 적다.

예를 들어 실시간 게임에서 이전 위치 정보가 조금 늦게 도착하는 것보다, 최신 위치 정보를 빠르게 받는 게 더 중요하다.
영상 통화에서도 중간에 한두 프레임이 깨지는 것보다 지연이 적은 게 더 중요하다.

**그래서 UDP는 실시간성이 중요한 통신에 사용한다.**
- 예) 실시간 게임, 영상 통화, 음성 통화, 스트리밍, DNS

## 언제 TCP를 쓰고, 언제 UDP를 쓸까?

정확히 도착해야 하는 데이터라면 TCP를 사용한다.
- 예를 들어 로그인, 결제, 파일 다운로드는 데이터가 일부라도 빠지면 문제가 된다.
이런 경우에는 속도보다 정확성이 중요하다.

반대로 조금의 손실보다 빠른 전달이 더 중요하다면 UDP를 사용한다.
- 예를 들어 실시간 게임이나 영상 통화에서는 오래된 데이터가 늦게 도착하는 것보다, 최신 데이터가 빠르게 도착하는 것이 더 중요하다.
