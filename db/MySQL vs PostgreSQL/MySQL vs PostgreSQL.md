# MySQL vs PostgreSQL

둘 다 `RDBMS`이다.
PostgreSQL은 MySQL보다 데이터 타입, 확장성, 동시성 제어, 데이터 무결성 측면에서 더 다양한 기능을 제공한다.

## 공통점

- 둘 다 `RDBMS`이다.
- 둘 다 `SQL`을 사용하여 데이터를 조회하고 변경할 수 있다.
- 둘 다 오픈소스이며, 개발자 커뮤니티가 활발하다.
- 둘 다 데이터 백업, 복제, 접근 제어 기능을 제공한다.

## 차이점

| 구분 | MySQL | PostgreSQL |
| --- | --- | --- |
| ACID | 스토리지 엔진에 따라 달라진다. | 기본적으로 지원한다. |
| 동시성 제어 | 스토리지 엔진에 따라 달라진다. | `MVCC`를 기본 동작으로 사용한다. |
| 인덱스 | `B-Tree`, `R-Tree` 등을 지원한다. | 다양한 인덱스를 지원한다. |
| 데이터 타입 | 일반적인 데이터 타입 중심 | 사용자 정의 타입, 배열, `JSONB` 등을 지원한다. |
| 뷰 | `View`를 지원한다. | View와 `Materialized View`를 지원한다. |
| 저장 프로시저 | 지원한다. | SQL 이외의 언어도 사용할 수 있다. |
| 트리거 | `BEFORE`, `AFTER` 트리거를 지원한다. | BEFORE, AFTER, `INSTEAD OF` 트리거를 지원한다. |

### ACID 지원

> 원자성, 일관성, 격리성, 지속성(ACID)은 오류가 발생해도 데이터베이스를 유효한 상태로 유지하기 위한 트랜잭션 속성이다.

MySQL은 사용하는 스토리지 엔진에 따라 ACID 지원 여부가 달라진다. 일반적으로 사용하는 `InnoDB`는 ACID를 지원한다.
PostgreSQL은 기본적으로 ACID를 지원한다.

### 동시성 제어

> 다중 버전 동시성 제어(MVCC)는 데이터를 바로 덮어쓰지 않고 여러 버전으로 관리하여 읽기와 쓰기의 충돌을 줄이는 방식이다.

MySQL은 스토리지 엔진에 따라 동시성 제어 방식이 달라진다. 예를 들어 InnoDB는 MVCC를 지원하지만, `MyISAM`은 MVCC를 지원하지 않는다.
PostgreSQL은 MVCC를 기본 동작으로 사용한다.

### 인덱스

> 인덱스를 사용하여 데이터를 더 빠르게 검색할 수 있다.

MySQL은 B-Tree, R-Tree 등의 인덱스를 지원한다.
PostgreSQL은 B-Tree뿐만 아니라 표현식 인덱스, 부분 인덱스, `Hash`, `GIN`, `GiST` 등 다양한 인덱스를 지원한다.

### 데이터 타입

MySQL은 관계형 데이터베이스이고, PostgreSQL은 객체 관계형 데이터베이스이다.
PostgreSQL은 사용자 정의 타입, 배열, JSONB, XML처럼 데이터를 더 유연하게 표현할 수 있는 기능을 제공한다.

### 뷰

> View는 데이터베이스 시스템이 여러 테이블에서 관련 데이터를 가져와서 만드는 가상의 테이블이다.

MySQL은 View를 지원한다.
PostgreSQL은 View뿐만 아니라 Materialized View도 지원한다.

Materialized View는 쿼리 결과를 미리 저장해두는 방식이다. 복잡한 쿼리의 조회 성능을 높일 수 있지만, 원본 데이터가 변경되면 갱신이 필요하다.

### 저장 프로시저

> 저장 프로시저는 미리 작성해 저장해둘 수 있는 SQL 쿼리 또는 코드 명령문이다.

MySQL과 PostgreSQL 모두 저장 프로시저를 지원한다.
PostgreSQL은 SQL 이외의 언어로 작성된 저장 프로시저도 사용할 수 있다.

### 트리거

> 트리거는 데이터베이스에서 특정 이벤트가 발생했을 때 자동으로 실행되는 작업이다.

MySQL은 INSERT, UPDATE, DELETE 문에 대해 BEFORE, AFTER 트리거를 사용할 수 있다.
PostgreSQL은 BEFORE, AFTER 트리거뿐만 아니라 INSTEAD OF 트리거도 지원한다.

## 무엇을 선택해야 하나요?

### 애플리케이션 범위

PostgreSQL은 쓰기 작업이 빈번하고 쿼리가 복잡한 애플리케이션에 적합하다.
MySQL은 구조가 단순하거나, 읽기 작업이 많고 데이터 변경이 많지 않은 서비스에 적합하다.

### 데이터베이스 개발 경험

MySQL은 상대적으로 학습 난이도가 낮고, 레퍼런스가 많아 처음 데이터베이스를 다룰 때 접근하기 쉽다.

### 성능 요구 사항

데이터 조회가 많다면 MySQL을, 데이터 변경이 잦고 복잡한 트랜잭션이 많다면 PostgreSQL을 우선 고려할 수 있다.
다만 성능은 데이터 구조, 인덱스, 쿼리, 설정, 하드웨어에 따라 달라지므로 단순히 제품 이름만으로 판단하기는 어렵다.

- 쓰기 성능
    - MySQL은 스토리지 엔진에 따라 쓰기 처리 방식이 달라진다. InnoDB는 Row-Level Lock과 MVCC를 사용한다.
    - PostgreSQL은 MVCC를 기본으로 사용하므로 쓰기 작업이 많고 동시성이 중요한 경우에 유리할 수 있다.

- 읽기 성능
    - PostgreSQL은 커넥션마다 프로세스를 사용하는 구조이기 때문에 커넥션 수가 많아지면 메모리 관리가 중요하다.
    - MySQL은 상대적으로 단순한 읽기 중심 서비스에서 많이 사용된다.
