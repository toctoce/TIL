# 단위 테스트 & 통합 테스트 & E2E 테스트 & 인수 테스트

## 단위 테스트(Unit Test)
단위 테스트는 가장 작은 단위(주로 클래스나 클래스의 메서드 단위)로 테스트하는 방법이다. 특정 기능이 설계대로 동작하는지를 확인한다.
JUnit, AssertJ, Mockito 라이브러리를 활용하여 단위 테스트를 작성한다.
테스트 대상이 외부 의존성에 의존하지 않도록 Mock 객체나, Stub을 사용해 의존성을 대체한다.
외부 시스템과 연결되지 않아 실행 속도가 빠르지만 전체 시스템의 동작을 검증할 수는 없다.
`@SpringBootTest`를 사용하면 Spring 컨텍스트를 로드해야하고 실행 속도가 느려진다. `@SpringBootTest`를 사용하지 않고 순수 Java 코드 수준에서 테스트를 작성한다.

## 통합 테스트(Integration Test)
통합 테스트는 여러 컴포넌트나 모듈이 함께 동작하는지 확인하는 테스트이다.
각 단위가 연결되어 올바르게 작동하는지 검증한다.
상호작용을 검증하는데 초점을 맞추기 때문에 실행 속도가 단위테스트보다 길다. 따라서 모든 시나리오보다는 핵심 시나리오들을 검증한다.
데이터베이스, 외부 API, 메시지 큐 등 실제 의존성을 사용하거나 테스트용 의존성(예, H2 인메모리 DB)을 따로 구현하여 테스트한다.

SpringBoot에서는 `@SpringBootTest`를 사용해 Spring 컨텍스트를 로드하고, 실제 애플리케이션 환경에 가까운 상태에서 테스트를 진행한다.

## E2E 테스트, 인수 테스트
E2E 테스트는 가장 넓은 범위의 테스트이다.
사용자가 경험할 수 있는 시나리오를 검증한다. 사용자 관점이기 때문에 UI를 포함하는 경우도 많다.

인수 테스트는 사용자가 겪는 시나리오를 순서에 맞게 api를 호출하여 검증하는 테스트이다. E2E 테스트보다는 범위가 작을 수 있지만, 여전히 넓은 범위를 검증합니다.


## 테스트 비중

단위테스트는 비용이 싸고 빠르다. 반면에 E2E 테스트는 비용이 비싸고 느리다. 때문에 E2E 테스트는 핵심 시나리오에 대해서만 검증하는 것이 좋다. 테스트 피라미드에 의하면 단위테스트는 60%, 통합 스트는 30%, E2E 테스트는 10% 비율로 테스트를 작성하는 것이 이상적이다.
