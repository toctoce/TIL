# 레드-블랙 트리

레드-블랙 트리는 이진 탐색 트리 중 하나이다.
기존의 이진 탐색 트리는 균형이 깨질 수 있기 때문에 최악의 경우 탐색이 `O(N)`이 될 수 있다.
레드-블랙 트리는 삽입, 삭제 시 균형을 맞춰주는 트리이기 때문에 이 문제를 해결할 수 있다.

## 용어
1. nil 노드
    - 존재하지 않음을 의미하는 노드
    - 자녀가 없을 때 자녀를 nil 노드로 표기한다.(레드-블랙 트리에서 leaf 노드는 nil 노드)
    - 값이 있는 노드와 동등하게 취급한다.

## 속성
레드-블랙 트리는 항상 아래 다섯 가지 속성을 만족한다.
1. 모든 노드는 빨간색 혹은 검은색이다.
2. 루트 노드는 검은색이다.
3. 모든 nil 노드는 검은색이다.
4. 빨간색 노드의 자식은 검은색이다.
5. 임의의 노드에서 nil 노드까지 가는 모든 경로의 검은색 노드 수는 같다. (자기 자신은 제외)

## 삽입 과정
삽입할 때는 빨간색 노드를 삽입한다. 일반적인 이진 탐색 트리와 같은 방식으로 삽입한다.
삽입 후에 레드-블랙 트리 위반 여부를 확인하고, 위반되었다면 재조정한다.

### 케이스 1. 루트 노드가 빨간색인 경우
루트 노드를 검은색으로 변경한다.

### 케이스 2. Double Red가 발생했고 삼촌 노드가 검은색인 경우
> Restructuring
> 1. 새로운 노드(N), 부모 노드(P), 조상 노드(G)를 오름차순으로 정렬한다.
> 2. 셋 중 중간값을 부모로 만들고 나머지 둘을 자식으로 만든다.
> 3. 새로 부모가 된 노드를 검은색으로 만들고 나머지 자식들을 빨간색으로 만든다.


![레드-블랙 트리 1](<레드-블랙 트리 1.png>)

세 노드를 정렬한 후 중간값을 검은색 부모로 만들고, 나머지 두 노드를 빨간색 자식으로 만든다.

### 케이스 3. Double Red가 발생했고 삼촌 노드가 빨간색인 경우

> Recoloring
> 1. 새로운 노드(N)의 부모(P)와 삼촌(U)을 검은색으로 바꾸고 조상(G)을 빨간색으로 바꾼다.
>       - 조상(G)이 루트 노드라면 검은색으로 바꾼다.
>       - 조상(G)을 빨간색으로 바꿨을 때 또다시 Double Red가 발생한다면 Restructuring/Recoloring을 진행해서 Double Red 문제가 발생하지 않을 때까지 반복한다.

![레드-블랙 트리 2](<레드-블랙 트리 2.png>)

부모와 삼촌을 검은색으로, 조상을 빨간색으로 바꾼다.
케이스 1 ~ 3이 다시 발생한다면 다시 해결한다.

## AVL과 차이

AVL 트리는 레드-블랙 트리보다 더 엄격하게 균형이 잡혀 있기 때문에 삽입과 삭제를 할 때 최악의 경우 더 많은 회전이 필요하다.
레드-블랙 트리는 실사용에 효율적이고, 최악의 경우에도 우수한 실행 시간을 보인다.

| 구분 | AVL Tree | Red-Black Tree |
| --- | --- | --- |
| 균형 기준 | 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이를 직접 제한 | 색깔 규칙으로 간접적으로 균형 유지 |
| 허용 범위 | 각 노드의 높이 차이 최대 `1` | 최장 경로가 최단 경로의 `2배`를 넘지 않음 |
| 균형 정도 | 더 엄격하게 균형 유지 | AVL보다 느슨하게 균형 유지 |
| 탐색 성능 | 더 빠른 편 | AVL보다 약간 느릴 수 있음 |
| 회전 빈도 | 회전이 더 자주 발생 | 색상 변경으로 해결되는 경우가 많고, 회전이 비교적 적음 |
| 적합한 경우 | 조회가 많은 경우 | 삽입/삭제가 많은 경우 |
| Java 사용 예 | 거의 사용 x | `TreeMap`, `TreeSet` |

## 활용: Java의 HashMap

`HashMap`은 해시 충돌에 대비해서 각 key에 대한 버킷을 가진다. 하나의 버킷에 여러 데이터가 들어가면 처음에는 `LinkedList`로 관리한다.
하지만 버킷 안의 데이터가 많아져 탐색 비용이 커지면 레드-블랙 트리로 변경한다.

```text
버킷에 데이터가 적은 경우

bucket[3] -> Node 1 -> Node 2 -> Node 3
```

```text
버킷에 데이터가 8개 이상인 경우

bucket[3]
    4
   / \
  2   6
 / \ / \
1  3 5  7
          \
           8
```

한 버킷에 저장된 노드가 8개 이상이면 `LinkedList` 대신 레드-블랙 트리를 사용해 탐색 시간을 `O(N)`에서 `O(logN)`으로 줄인다.
