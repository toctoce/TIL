# Web Server & WAS

> Web Server: 정적 콘텐츠를 제공하는 서버
>
> WAS: 동적 로직을 처리하는 서버

## Web Server

Web Server는 사용자가 접속했을 때 브라우저에 필요한 정적 파일을 전달하는 역할을 한다.

- HTML, CSS
- JavaScript
- 이미지 파일
- 동영상 파일

대표적으로 Nginx, Apache가 있다.

## WAS (Web Application Server)

WAS는 웹 애플리케이션을 실행하고, 실제 비즈니스 로직을 처리하는 서버이다.
예를 들면 다음과 같은 기능이 WAS에서 처리된다.

- 로그인 처리
- 회원가입
- 상품 주문
- 결제 요청
- 게시글 등록
- 관리자 기능

대표적으로 Tomcat 등이 있다.

### 왜 필요한가?

동적인 콘텐츠를 제공해야 할 때 필요하다.
사용자 요청에 따라 DB를 조회하거나, 데이터를 저장하거나, 비즈니스 로직을 실행한 뒤 응답을 만들어야 하기 때문이다.

## 왜 나눌까?

서버 한 대에서 정적 콘텐츠 처리와 동적 로직 처리를 모두 할 수도 있다.
하지만 서비스 규모가 커질수록 Web Server와 WAS를 분리하는 것이 유리하다.

![Web Server와 WAS의 요청 처리 구조](<Web Server & WAS 1.png>)

WAS는 DB 조회 및 다양한 비즈니스 로직 처리에 집중해야 한다.
단순한 정적 콘텐츠는 Web Server가 처리하도록 역할을 분리하면 WAS의 부하를 줄일 수 있다.
만약 WAS가 정적 콘텐츠 요청까지 모두 처리하면 부하가 커지고, 동적 콘텐츠 처리가 지연되어 응답 속도가 느려질 수 있다.

- 속도: 이미지나 파일은 Web Server가 처리하고, 복잡한 기능은 WAS가 담당하면 효율적이다.
- 안정성: WAS에 부하가 걸려도 Web Server는 별도로 동작할 수 있다.

![여러 WAS로 확장한 구조](<Web Server & WAS 2.png>)

사용자가 많은 서비스에서는 WAS를 여러 대로 구성할 수 있다.
이때 특정 WAS에 문제가 생기면 앞단의 Web Server는 해당 WAS로 요청을 전달하지 않도록 제외할 수 있다.
문제가 발생한 WAS를 재시작하는 동안 나머지 WAS가 요청을 계속 처리하면 사용자는 서비스를 계속 이용할 수 있다.

- 확장성: 사용자가 늘어나면 WAS만 여러 대로 늘리는 구조도 가능하다.
