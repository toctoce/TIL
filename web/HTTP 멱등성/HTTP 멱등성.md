# HTTP 멱등성

> HTTP 멱등성: 동일한 요청을 여러 번 보내도 서버의 의도된 상태에 미치는 영향이 한 번 보낸 것과 같은 성질

HTTP에서 멱등성은 응답이 항상 같다는 의미가 아니라, 서버 상태에 미치는 영향이 같다는 의미이다.

## HTTP 메서드별 멱등성

HTTP 메서드에도 멱등성이 있다. 예를 들어 `GET`은 같은 요청을 여러 번 보내도 서버의 리소스 상태를 변경하지 않으므로 멱등하다.

대표적인 메서드에 대한 멱등성은 아래와 같다.

| HTTP 메서드 | 멱등성 |
| --- | --- |
| `GET` | O |
| `PUT` | O |
| `DELETE` | O |
| `POST` | X |
| `PATCH` | X |

### 멱등한 메서드

`GET`과 `PUT`처럼 리소스를 조회하거나 대체하는 메서드는 멱등하다. `PUT`은 여러 번 호출해도 매번 같은 리소스 상태로 대체한다.

`DELETE`도 여러 번 호출한 뒤의 서버 상태는 리소스가 삭제된 상태로 같기 때문에 멱등하다. 다만 요청마다 응답 상태 코드는 달라질 수 있다.

### 멱등하지 않은 메서드

`POST`와 `PATCH`는 기본적으로 멱등성이 보장되지 않는다. 다만 API 동작을 멱등하게 설계하거나 멱등키를 적용하면 안전한 재시도를 지원할 수 있다.

## API에서의 멱등성

멱등한 API라면 같은 요청을 두 번 이상 보내도 서버 상태에 미치는 영향은 한 번 보낸 경우와 같다.

시스템에 의도하지 않은 문제를 일으키지 않고 요청을 재시도할 수 있기 때문에, 멱등성은 안전한 API를 만드는 데 중요하다.

예를 들어 결제 API가 멱등하다면 동일한 요청이 중복으로 전송되더라도 결제는 한 번만 처리된다. 클라이언트가 응답을 받지 못한 경우에도 같은 요청을 안전하게 재시도할 수 있다.

## 멱등성 보장 방법

멱등성을 보장하려면 멱등키를 API 요청에 포함하면 된다. 

서버는 이전 요청과 멱등키가 같다면, 다시 처리하지 않은 채 처음 저장한 응답을 반환한다.

멱등키는 헤더, 요청 본문, 쿼리 파라미터 등에 포함할 수 있다. 일반적으로 HTTP 헤더에 담는걸 권장한다.

```http
Idempotency-Key: {IDEMPOTENCY_KEY}
```

```bash
curl --request POST \
  --url https://api.tosspayments.com/v1/payments/5zJ4xY7m0kODnyRp/cancel \
  --header 'Authorization: Basic dGVzdF9nc2tfZG9jc19PYVB6OEw1S2RtUVhrelJ6M3k0N0JNdzY6' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: SAAABPQbcqjEXiDL' \
  --data '{"cancelReason":"구매자 변심"}'
```

## 멱등성 처리 과정

결제 취소 API를 예시로 멱등키를 처리하는 과정을 살펴본다.

![멱등성 처리 과정](<HTTP 멱등성 1.png>)

1. API 서버는 취소 요청의 헤더에 멱등키가 있는지 확인한다.
2. 멱등키가 포함된 요청을 받으면 DB에서 해당 멱등키와 일치하는 요청 기록을 조회한다.
   - 멱등키의 유효 기간을 정할 수 있다.
3. 같은 멱등키의 요청 기록이 있다면 실제 요청을 다시 실행하지 않고 저장된 응답을 반환한다.
4. 같은 멱등키의 요청 기록이 없다면 요청을 처리하고 멱등키와 응답을 DB에 저장한 뒤 클라이언트에 반환한다.
