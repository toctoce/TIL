# TCP 흐름제어

> 송신측과 수신측의 데이터 처리 속도 차이를 해결하기 위한 기법

송신측의 전송 속도가 수신측의 처리 속도보다 빠르면 문제가 생긴다.
수신 버퍼의 남은 공간을 초과해 데이터가 도착하면 데이터가 손실될 수 있고, 불필요한 데이터 전송이 반복될 수 있다.

- 수신 버퍼 : 수신자가 받은 데이터를 잠깐 저장해두는 공간

  ```text
  송신자 → 데이터 → 수신 버퍼 → 애플리케이션이 읽음
  ```

- 수신 윈도우 : 수신자가 송신자에게 알려주는 “더 받을 수 있는 데이터 양”(수신 버퍼의 남은 공간)
  - 수신자는 ACK를 보낼 때 수신 윈도우 크기인 `rwnd`를 함께 알려준다.([TCP 헤더에 존재함](<../TCP 헤더/TCP 헤더.md#window>))

이를 방지하기 위해 수신측의 처리 속도에 맞게 송신측의 전송 속도를 조절한다.

## 흐름제어 방식

### Stop and Wait

> 매번 전송한 패킷에 대해 확인 응답을 받아야만 그 다음 패킷을 전송하는 방법

![TCP 흐름제어 1](<TCP 흐름제어 1.png>)

하지만 데이터를 하나 보내고 ACK를 기다리면 너무 느리다. TCP 흐름제어에서는 여러 데이터를 연속해서 보낼 수 있는 Sliding Window를 사용한다.

### Sliding Window

> 송신자가 한 번에 보낼 수 있는 데이터 범위를 관리하는 방식

예를 들어 한 번에 4개까지 보낼 수 있다고 해보면:

```text
전송 가능 범위
[1] [2] [3] [4] 5 6 7 8 9
```

송신자는 1, 2, 3, 4를 보낼 수 있다.
수신자가 1, 2를 받았다고 ACK를 보내면 윈도우가 오른쪽으로 이동한다.

```text
전송 가능 범위
1 2 [3] [4] [5] [6] 7 8 9
```

## 수신자 - rwnd 계산 과정

```text
RcvBuffer: 수신자에게 할당된 수신 버퍼의 전체 크기
LastByteRead: 애플리케이션이 수신 버퍼에서 읽어 간 마지막 바이트 번호
LastByteRcvd: 네트워크에서 도착하여 수신 버퍼에 저장된 마지막 바이트 번호
```

수신 버퍼에 아직 남아 있는 데이터의 양은 다음과 같다.

`수신 버퍼에 남아있는 데이터 양` = `LastByteRcvd` - `LastByteRead`

`rwnd` = `RcvBuffer` - `수신 버퍼에 남아있는 데이터 양` = `RcvBuffer` - (`LastByteRcvd` - `LastByteRead`)

## 송신자 - rwnd로 데이터를 조절

```text
LastByteSent: 송신자가 마지막으로 보낸 바이트 번호
LastByteAcked: 송신자가 ACK를 통해 확인받은 마지막 바이트 번호
```

아직 ACK를 받지 못한 데이터의 양은 다음과 같다.

`ACK를 받지 못한 데이터의 양` = `LastByteSent` - `LastByteAcked`

송신자는 ACK를 받지 못한 데이터의 양이 `rwnd`를 넘지 않도록 유지해야 한다.

`rwnd`를 넘는다면 새 데이터 전송을 멈추거나 줄이고, `ACK` 또는 수신 윈도우 갱신을 기다린다.
