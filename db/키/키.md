# 키(Key)

> 테이블에서 행을 식별하거나, 테이블 간의 관계를 맺기 위해 사용하는 속성
> 
> 슈퍼키, 후보키, 기본키, 대체키, 자연키, 대리키, 외래키, 복합키, 유니크키

## 키 간의 관계

```
슈퍼키
  └─ 후보키 (유일성 + 최소성)
        ├─ 기본키 (대표로 선택된 것)
        │     ├─ 자연키 → 실제 비즈니스 데이터 (주민등록번호, 이메일 등)
        │     └─ 대리키 → 인공적으로 만든 식별값 (AUTO_INCREMENT, UUID)
        └─ 대체키 (선택되지 않은 나머지)

외래키   → 다른 테이블의 기본키를 참조
복합키   → 두 개 이상의 속성으로 구성
유니크키 → NULL 허용 + 중복 불가
```

## 식별을 위한 키

테이블의 행을 유일하게 식별하기 위한 키들이다.

### 1. 슈퍼키(Super Key)

- **행을 유일하게 식별할 수 있는** 속성의 집합
- 유일성(Uniqueness)만 만족하면 됨 → 최소성은 필요 없음
- 예: `{학번}`, `{학번, 이름}`, `{학번, 이름, 나이}` 모두 슈퍼키

### 2. 후보키(Candidate Key)

- 슈퍼키 중에서 **최소성**까지 만족하는 키
- 즉, 속성을 하나라도 제거하면 유일성이 깨지는 키
- **유일성 + 최소성** 모두 만족
- 예: `{학번}`, `{주민등록번호}` → 후보키  
  `{학번, 이름}` → 학번만으로도 식별 가능하므로 후보키 아님

### 3. 기본키(Primary Key)

- 후보키 중에서 **설계자가 선택한 대표 키**
- **NULL 불가**, **중복 불가**
- 테이블당 오직 하나만 존재
- 예: `학번`, `주문ID`

### 4. 대체키(Alternate Key)

- 후보키 중에서 **기본키로 선택되지 않은** 나머지 키
- 예: 기본키가 `학번`이면, `주민등록번호`는 대체키

## 그 외 키의 분류

식별 방식, 관계 설정, 제약 조건, 구성 방식에 따라 함께 알아두면 좋은 키들이다.

### 1. 자연키(Natural Key), 대리키(Surrogate Key)

- 자연키는 **실제 비즈니스 데이터**를 식별자로 사용하는 키
- 대리키는 **비즈니스와 무관하게 식별 목적으로만 인위적으로 만든 키**
- 대리키는 주로 `AUTO_INCREMENT`, `UUID` 등을 사용
- 예: 자연키는 `주민등록번호`, `이메일`, 대리키는 `회원ID`, `주문ID`

### 2. 외래키(Foreign Key)

- **다른 테이블의 기본키를 참조**하는 속성
- 테이블 간의 관계(참조 무결성)를 보장
- 참조되는 값은 반드시 부모 테이블의 기본키에 존재해야 함
- NULL 허용 가능 (선택적 관계 표현 시)
- 예: `주문` 테이블의 `회원ID` → `회원` 테이블의 `회원ID`(PK) 참조

### 3. 복합키(Composite Key)

- **두 개 이상의 속성**으로 구성된 키
- 각 속성 단독으로는 유일하지 않지만, 조합하면 유일성 보장
- 예: `{학번, 과목코드}` → 수강 테이블에서 한 학생이 여러 과목 수강 가능

### 4. 유니크키(Unique Key)

- 특정 컬럼에 **중복 값을 허용하지 않는** 제약 조건
- 단, **NULL은 허용** (MySQL 기준)
- 테이블에 여러 개 존재 가능
- 예: `이메일`, `전화번호` 컬럼에 UNIQUE 제약 조건 부여
