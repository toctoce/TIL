# POST & PUT & PATCH

## POST

- `POST` 요청의 본문은 대상 리소스에 정의된 방식으로 처리된다. 즉, 클라이언트가 요청을 보내면 서버가 정의된 로직에 따라 처리한다.
- `POST`로 리소스를 생성할 때는 클라이언트가 새 리소스의 `URI`를 미리 알 필요가 없다.
- 새로운 결제를 생성하려면 `/payments`라는 결제 컬렉션의 `URI`로 요청을 보낸다. 서버는 `/payments/1`과 같은 새로운 결제 리소스를 생성한다.
- `POST`는 멱등하지 않다. 같은 요청을 `/payments`로 세 번 보내면 `/payments/1`, `/payments/2`, `/payments/3`과 같이 동일한 데이터를 가진 리소스가 세 개 생성될 수 있다.
- `POST`는 리소스 생성뿐만 아니라 **서버에서 정의한 다양한 작업**을 처리할 수 있는 메서드이다.

## PUT

- `PUT` 요청에서는 생성시에도 클라이언트가 `/payments/1`과 같이 대상 리소스의 정확한 `URI`를 알아야 한다.
- `PUT`은 멱등하다.
- `PUT`은 리소스를 생성하거나 전체 상태를 대체할 때 사용한다.
- `PUT`은 요청 본문으로 전달한 표현으로 리소스의 전체 상태를 대체하므로, 일부만 수정하고 싶어도 전체 데이터를 포함해야 한다.

## PATCH

- `PATCH`도 `PUT`과 같이 대상 리소스의 정확한 `URI`를 알아야 한다.
- `PUT`은 리소스 전체를 대체하지만, `PATCH`는 요청에 따라 리소스의 일부를 수정한다.
- 일반적으로 변경할 필드만 요청 본문에 포함하고, 변경하지 않을 필드는 생략한다.
- `PATCH`는 멱등하지 않다. 따라서 여러 `PATCH` 요청이 동시에 처리되면 변경 내용이 충돌하여 데이터가 손실될 수 있다.

## 비교

메서드 종류는 클라이언트의 상황에 따라 유연하게 사용하면 됩니다.

| 메서드 | 설명                        | 일반적인 요청 URI   | 멱등성 |
| --- |---------------------------|---------------| --- |
| `POST` | 리소스 생성 또는 서버에서 정의한 다양한 작업 | 리소스 컬렉션 `URI` | X |
| `PUT` | 리소스 생성 또는 전체 대체           | 특정 리소스 `URI`  | O |
| `PATCH` | 리소스 일부 수정                 | 특정 리소스 `URI`  | X |
