## UDP Header

UDP(User Datagram Protocol) 헤더는 모든 UDP 데이터그램의 시작 부분에 있는 8바이트 구조이다.
이 헤더는 애플리케이션 간 데이터 전송에 필요한 최소한의 정보만 제공하며, 오버헤드를 최소화합니다.

UDP 헤더와 그 안의 여러 필드를 더 자세히 살펴보자.

![UDP 헤더 1](UDP%20%ED%97%A4%EB%8D%94%201.svg)

IPv4 헤더와 달리 UDP 헤더에는 옵션이 없고, 8바이트의 고정된 구조입니다. 
UDP는 간단하며 안정성이 필요하지 않은 애플리케이션에 적합합니다.

### Source Port

출발지 포트는 **16비트 필드**이며, 송신자의 포트 번호를 나타낸다.

### Destination Port

목적지 포트는 **16비트 필드**이며, 수신자의 포트 번호를 나타낸다.

### Length

길이는 **16비트 필드**이며, UDP 데이터그램의 전체 길이(바이트)를 나타낸다.
- 최솟값은 데이터가 없는 경우 최소 8바이트이다.
- 최댓값은 이론적으로 65535바이트이다.
  - 데이터 구조는 `[ IPv4 헤더 ][ UDP 헤더 ][ UDP 데이터 ]`이며, IPv4 헤더는 최소 20바이트이다. UDP 헤더는 8바이트이므로 UDP 페이로드의 최댓값은 65535 - 20 - 8 = 65507바이트이다. 
  - 하지만 실제 최댓값은 IP 계층에 의해 제한된다.

#### Practical Message Sizing

프로토콜상으로는 큰 데이터그램을 허용하지만, 실무에서는약 1400~1450바이트 정도로 유지하는 것이 좋다.
대부분의 네트워크 이더넷에서 MTU(Maximum Transmission Unit)은 1500바이트이다. IP 헤더 20바이트, UDP 헤더 8바이트를 고려하면 페이로드는 최대 1472바이트이다.
이 한계보다 약간 낮은 1400~1450바이트로 설정해야 추가 헤더, 확장 헤더 등에 대한 여유 공간을 확보할 수 있다.

> UDP 데이터그램이 경로 MTU를 초과하면, IP 계층은 이를 여러 개의 패킷으로 분할(fragmentation) 한다.
> 분할된 패킷은 목적지에서 다시 조립되어야 하므로, 처리 오버헤드가 추가된다.
>
> ☠️ 게다가 하나의 조각이라도 손실되면, UDP에는 재전송 메커1니즘이 없기 때문에 전체 데이터그램이 손실된다.

### Checksum

체크섬은 **16비트 필드**이며, UDP 헤더와 데이터에 대한 오류 검출 기능을 제공한다.

IPv4 헤더 체크섬과 달리, UDP 체크섬은 전체 페이로드를 포함합니다. 

체크섬은 IPv4에서는 선택 사항이며, 사용하지 않을 경우 0으로 설정됩니다. 하지만 IPv6에서는 필수입니다.

> UDP 체크섬 계산 결과가 우연히 0x0000이 나올 수 있다.
> 그런데 IPv4 UDP에서 체크섬 값 0x0000은 “체크섬을 사용하지 않는다”는 의미로 쓰입니다. 
> 그래서 실제 계산 결과가 0x0000이면, 전송할 때는 0xFFFF로 바꿔서 보냅니다.

#### pseudo-header 추가

의사 헤더 구성
- Source IP address
- Destination IP address
- Protocol (17 for UDP)
- UDP length

UDP 체크섬 계산할 때는 실제 UDP 헤더만 보는 게 아니라, 의사 헤더를 추가하여 계산한다.(실제 UDP 헤더에 붙어서 전송되는 것은 아니다.)
올바른 MAC 주소뿐 아니라 **올바른 IP 주소에 도달했는지**도 보장할 수 있다.
